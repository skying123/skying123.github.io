版本：适用于 Playwright Python 2026.x | 语言：Python 3.9+
官方文档：https://playwright.dev/python/

一、核心专业术语表（Glossary）

术语 英文全称 定义
浏览器实例 Browser 浏览器进程实体（Chromium/Firefox/WebKit），启动成本较高，一个实例可创建多个 Context
浏览器上下文 BrowserContext 独立的浏览器会话环境（类似无痕窗口），拥有隔离的 Cookie、缓存、Storage、LocalStorage，是并行测试的隔离单元
页面/标签页 Page 浏览器上下文中的单个标签页，是执行导航、交互、断言的主要对象
定位器 Locator 对页面元素的”查询描述”，惰性求值，支持链式过滤与自动重试，是 Playwright 推荐的元素查找方式
帧/框架 Frame 页面中的 iframe 或框架，每个 Frame 拥有独立的 DOM 和 Execution Context
路由拦截 Route 通过 page.route() 拦截网络请求，可实现 Mock、修改请求头、断点调试
Fixture Test Fixture 测试夹具，封装测试的前置准备（Setup）与后置清理（Teardown），通过 pytest fixture 机制自定义
分片 Shard 将测试套件水平拆分到多台 CI 机器执行（如 --shard=1/4），用于大规模套件横向扩容
工作进程 Worker 在单台机器内并行执行测试的进程数，依赖测试完全隔离
追踪 Trace 测试执行过程的全量记录，包含截图、DOM 快照、网络日志、控制台输出，通过 Trace Viewer 可视化回放
存储状态 Storage State 浏览器上下文的持久化状态（Cookie、LocalStorage），通过 storage_state 保存/加载，用于跳过重复登录
POM Page Object Model 页面对象模型，将页面元素定位与业务操作封装为类，实现测试逻辑与 UI 逻辑解耦
软断言 Soft Assertion 断言失败时不立即终止测试，继续执行后续步骤，最后统一汇总失败结果
自动等待 Auto-waiting Playwright 在执行操作前自动执行可操作性检查（可见、稳定、接收事件），无需手动 sleep

四、常见问题与解决方案（Troubleshooting）

问题现象 根因分析 解决方案
测试本地通过，CI 失败（flaky） 1. 固定 sleep 导致竞态条件
2. 选择器不稳定（CSS class 动态生成）
3. CI 资源不足导致加载慢		 1. 移除所有 page.wait_for_timeout，改用自动等待或 expect.to_pass
2. 改用 get_by_role / get_by_test_id 等语义化定位器
3. 增加重试与 workers 调优
element is not visible/enabled 报错 元素在 DOM 中但不可交互（被遮罩、动画中、未聚焦） 使用 locator.scroll_into_view_if_needed() 前置滚动；检查是否有悬浮遮罩层；对动画元素增加 expect(locator).to_be_visible() 前置断言
登录测试极慢 每个测试都走完整 UI 登录流程 使用全局 conftest.py 中的 generate_auth_state fixture 登录一次并保存 storage_state，后续测试直接复用 Cookie/LocalStorage
并行测试数据冲突 多个 Worker 操作同一数据库记录 1. 使用唯一测试数据（UUID/时间戳后缀）
2. 通过 API 在 yield 之后的 teardown 中清理数据
3. 使用 pytest.mark.xdist_group(name="serial") 强制串行（仅限必须共享数据的场景）
弹窗/新标签页处理失败 未正确等待事件触发 使用 with context.expect_page() as new_page_info: 上下文管理器确保监听在操作之前建立
文件上传 set_input_files 无效 目标元素非 <input type="file"> 或处于 Shadow DOM 确保定位到原生 input 元素；若被组件库隐藏，使用 page.locator('input[type="file"]') 直接定位（即使 CSS 隐藏 Playwright 也支持）
视觉回归 to_have_screenshot 微差失败 字体渲染、动画、时间戳差异 配置 max_diff_pixels 与 threshold；对动态内容区域使用 mask 参数遮罩
Trace/Screenshot 未生成 配置项作用域错误或测试提前退出 确认 context.tracing.start() 在 conftest.py 中正确配置；检查 pytest_runtest_makereport 钩子是否正确捕获失败
WebKit 测试行为与 Safari 真机不一致 Playwright WebKit 基于开源 WebKit，与 Apple Safari 部分特性存在差异 关键场景使用 BrowserStack 等真机云补充测试；对 iOS 特有 API（如 Apple Pay）使用真机或模拟器
Chrome Extension Manifest V2 测试失败 Playwright 1.48+ 不再支持 Manifest V2，仅支持 V3 升级被测插件至 Manifest V3 标准；或锁定旧版本 Playwright（不推荐）
Python 路径导入错误（ModuleNotFoundError） 项目根目录未加入 PYTHONPATH 在 pytest.ini 中配置 pythonpath = .；或使用 python -m pytest 运行（自动将当前目录加入路径）
网络拦截 route.fulfill 后页面仍请求真实后端 拦截模式不匹配或存在 CORS 预检请求 使用 page.route("**/*", ...) 通配确保覆盖；对 OPTIONS 预检请求单独处理；检查 route.continue_() 与 route.fulfill() 使用场景
测试执行顺序依赖导致分片失败 测试间存在隐式状态耦合（全局变量、共享文件） 确保每个测试使用全新 context；避免全局状态；使用 autouse=True 的 fixture 在每个测试前重置状态
移动端模拟测试通过但真机失败 仅模拟 viewport，未模拟 touch 事件或 meta viewport 使用 p.devices["iPhone 15 Pro"] 完整描述符（含 is_mobile, has_touch, user_agent）；对触摸手势使用 locator.tap() 而非 click()
pytest-playwright 的 page fixture 与自定义冲突 命名冲突或 fixture 作用域不一致 自定义 page fixture 使用不同名称（如 custom_page），或在 conftest.py 中覆盖默认 fixture
Allure 报告中文乱码 Allure 默认编码问题 确保系统 locale 为 UTF-8；在 CI 中设置 LANG=en_US.UTF-8；使用 allure-pytest 最新版本

六、Python vs TypeScript API 差异速查

功能 Python API TypeScript API
启动浏览器 p.chromium.launch(headless=True) chromium.launch({ headless: true })
创建上下文 browser.new_context(viewport=...) browser.newContext({ viewport: ... })
元素点击 locator.click() locator.click()
填充输入 locator.fill("text") locator.fill('text')
断言可见 expect(locator).to_be_visible() await expect(locator).toBeVisible()
路由拦截 page.route(url, handler) await page.route(url, handler)
截图 page.screenshot(path="...") await page.screenshot({ path: '...' })
Trace 开始 context.tracing.start(...) await context.tracing.start(...)
软断言 expect.soft(locator).to_be_visible() await expect.soft(locator).toBeVisible()
属性命名 snake_case（如 slow_mo） camelCase（如 slowMo）
异步支持 async_playwright + await 原生 async/await
测试框架 pytest + pytest-playwright @playwright/test
Fixture 机制 pytest.fixture test.extend()
